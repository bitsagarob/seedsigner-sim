# sha256 of every committed file that ends up in front of a visitor.
#
# Everything fetched is already content-addressed where it is fetched: the wallet
# and its Python dependencies by build/build-wallet-zip.sh, the Pyodide runtime
# by build/fetch-assets.sh. This file is the other half, the files that live in
# the repository and are served or packaged as they are. Without it "you can read
# all of it" is a claim about a moving target; with it, a change to any of them
# is a line in a diff that somebody had to write on purpose.
#
# Check them from the repository root with either of:
#
#     sha256sum -c build/checksums.txt
#     ./build/fetch-assets.sh --check
#
# build/build-wallet-zip.sh checks the two package directories below against this
# file as well, before it stages either into a zip, and refuses to package a file
# that is not listed here at all. Updating a stand-in therefore means updating
# this file in the same commit, which is the point: the zip's hash moves when they
# change, and a hash that moves without a diff to point at is the thing this
# repository exists to make impossible.
#
#     git ls-files src/smartcard src/fakes | LC_ALL=C sort | xargs sha256sum
#
# regenerates the last block, for when a change to one of them is deliberate.
#
# jsQR 1.4.0, Apache-2.0. This is the file published as dist/jsQR.js in the npm
# package jsqr@1.4.0, unmodified. To confirm that independently, and not just
# that it matches the line below:
#
#     curl -sL https://registry.npmjs.org/jsqr/-/jsqr-1.4.0.tgz | tar xzO package/dist/jsQR.js | sha256sum
#
